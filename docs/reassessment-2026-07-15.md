# DuckRabbit RedTeam publication-readiness reassessment — 2026-07-15

This reassessment applies the FirstPrinciples, RedTeam, and Loop workflows to
the current project state. The object being built is not a perceptual illusion
itself. It is a typed transformation and verification system:

\[
q=(i,\theta,s,e) \rightarrow A=G_i(\theta;s) \rightarrow F=E_e(A)
\rightarrow I=D(F) \rightarrow V(F,M).
\]

The irreducible contracts are finite canonical arrays, deterministic hashes,
valid media clocks, explicit evidence lineage, and a separation between
physical stimulus facts and observer hypotheses. Codec convenience, figure
counts, and manuscript prose are downstream constraints.

## Challenge findings

The red-team pass found four concrete weaknesses. The shared parent worktree
could be switched by another process during pytest, invalidating coverage and
making missing source appear to be a package failure. The evidence loader
coerced malformed JSON values through `str(...)`. RGB `mean_luminance` was a
channel mean rather than relative luminance. The observer harness generated
binary synthetic data but did not provide typed continuous, count, or reaction
time records. These are now addressed by isolated-worktree guidance, strict
field parsing, Rec. 709 luminance, `MetricSuite` v2, typed synthetic records,
and an independent `duckrabbit audit` command.

## Domain expansion

Zöllner and auditory continuity are now implemented as deterministic,
source-linked engineering constructions. Their promotion gates include typed
parameters, finite/range invariants, canonical determinism, objective metrics,
scholarly records, and limitations. The code does not claim that line
orientation or auditory continuity is perceived by every observer. McGurk
remains `input_required` pending checksummed speech fixtures, licensing or
consent records, and a preregistered validation contract.

## Loop record

The iterative cycles were:

1. **Observe:** reconcile remote refs, inspect guidance, run a clean baseline.
2. **Think:** identify coercion, metric semantics, observer-schema, catalog, and
   worktree failure modes.
3. **Plan:** repair verifier boundaries first, then promote only fully
   contracted families, then update publication and documentation state.
4. **Build:** implement strict evidence parsing, metric v2, generators,
   synthetic observer families, audit CLI, scholarship records, and docs.
5. **Verify:** run Ruff, real tests, coverage, publication generation, and the
   independent audit from a stable project worktree.
6. **Learn:** keep the parent monorepo's unrelated dirty changes isolated and
   retain warnings for absent disposable outputs rather than hiding them.

Residual epistemic limits are deliberate: no participant results, no universal
perceptual claims, no claim that a literature citation validates a pixel-level
replication, and no promotion of input-dependent speech without a lawful and
validated fixture.
